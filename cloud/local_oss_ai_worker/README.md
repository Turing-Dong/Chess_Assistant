# Local OSS AI Worker

This worker runs on a second computer. It replaces the Aliyun FC handler during
development:

1. ESP32 uploads `devices/<device_id>/requests/<frame_id>.jpg`.
2. ESP32 uploads `devices/<device_id>/requests/latest.json`.
3. This worker polls `latest.json`, downloads the image, and calls
   `process_image`.
4. The worker writes `devices/<device_id>/results/<frame_id>.json`.
5. ESP32 keeps its existing result polling flow.

The current `process_image` implementation returns fixed placeholder moves. It
is intentionally protocol-compatible with `cloud/aliyun_fc_oss_handler/index.py`
so that the local AI implementation can be added without changing ESP32 code.

Device IDs are generated by firmware from each board's full Wi-Fi STA MAC as
`chess-XXXXXXXXXXXX`. They are stable per board, so users do not need to look
up MAC addresses manually.

## Install

Use a RAM user or temporary STS credentials with read/write permission for the
target OSS bucket. Do not commit secrets to this repository.

```powershell
cd cloud/local_oss_ai_worker
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Set credentials in the second computer's shell:

```powershell
$env:ALIYUN_ACCESS_KEY_ID="your-access-key-id"
$env:ALIYUN_ACCESS_KEY_SECRET="your-access-key-secret"
# Optional when using STS:
# $env:ALIYUN_SECURITY_TOKEN="your-security-token"
```

Set the AI service key as a separate local environment variable. Do not write it
into source files or commit it to git:

```powershell
$env:CHESS_AI_API_KEY="your-ai-api-key"
$env:CHESS_AI_PROVIDER="qwen"
$env:CHESS_AI_MODEL="qwen3-vl-plus"
```

Use `CHESS_AI_PROVIDER=qwen` for Alibaba Cloud Model Studio / DashScope
OpenAI-compatible chat completions. Use `CHESS_AI_PROVIDER=openai` for OpenAI
Responses API. The worker also accepts `OPENAI_API_KEY` if you prefer that
variable name for OpenAI.

Alternatively, create a local `.env` file next to `worker.py`. The real `.env`
file is ignored by git:

```powershell
Copy-Item .env.example .env
notepad .env
```

## Run

On Windows, double-click `run_worker.bat`. On the first run it creates `.env`
from `.env.example`; fill in `OSS_BUCKET`, `DEVICE_IDS`, and credentials, then
run the bat again.

For one device:

```powershell
python worker.py `
  --bucket esp32-chess-assistant `
  --device-id chess-AABBCCDDEEFF `
  --region cn-hangzhou `
  --debug-dir debug
```

For multiple known devices:

```powershell
python worker.py `
  --bucket esp32-chess-assistant `
  --device-ids chess-AABBCCDDEEFF,chess-112233445566 `
  --region cn-hangzhou `
  --debug-dir debug
```

In `.env`, use either the old single-device setting:

```text
DEVICE_ID=chess-AABBCCDDEEFF
```

or the multi-device setting:

```text
DEVICE_IDS=chess-AABBCCDDEEFF,chess-112233445566,chess-778899AABBCC
```

If you want the worker to scan OSS for existing
`devices/<device_id>/requests/latest.json` objects, enable discovery:

```text
DISCOVER_DEVICES=true
```

The worker loads `.env` by default. To use another path:

```powershell
python worker.py --bucket esp32-chess-assistant --device-ids chess-AABBCCDDEEFF,chess-112233445566 --env-file C:\secure\chess-worker.env
```

If you prefer a different environment variable name for the AI key:

```powershell
python worker.py --bucket esp32-chess-assistant --device-ids chess-AABBCCDDEEFF,chess-112233445566 --ai-api-key-env MY_AI_KEY
```

For one-shot testing:

```powershell
python worker.py --bucket esp32-chess-assistant --device-ids chess-AABBCCDDEEFF,chess-112233445566 --once
```

## AI Integration Point

Replace `process_image` in `worker.py` with the real pipeline:

```text
OpenAI vision -> structured move points
or later:
decode JPEG -> locate/rectify Xiangqi board -> detect pieces -> build board/FEN
-> run Xiangqi engine -> return player-local points
```

Keep these result fields stable because ESP32 currently validates them:

- `protocol_version`
- `device_id`
- `session_id`
- `frame_id`
- `sequence`
- `status`
- `image_width`
- `image_height`
- `confidence`
- `points.player1_start`
- `points.player1_end`
- `points.player2_start`
- `points.player2_end`
